# Deviations from the specification

The implementing agent records here every place where the implementation differs from ARCHITECTURE.md or the docs, for example because the DeepStream 9.1 public headers or behaviour differ from what the spec assumed.

| 7 | 2026-11-20 | IMPLEMENTATION_PLAN M1 "SIGINT/SIGTERM → EOS" | Signals only quit the main loop; EOS is sent by DeepStream's `destroy_pipeline()`, which sends EOS, drains the bus until EOS and sets NULL. | 8 | 2026-11-20 | IMPLEMENTATION_PLAN M1 "SIGTERM exits 0"; ARCHITECTURE §4.1 (EOS, set NULL, destroy) | **DeepStream 9.1 bug workaround.** Once any stream has been added to `nvmultiurisrcbin` (still active or already removed), `destroy_pipeline()` blocks forever while setting the pipeline to NULL. `rtvision` bounds teardown with a watchdog (`--shutdown-timeout`, default 8 s, below Docker's 10 s stop grace) that logs `event=shutdown_timeout` at warn level and `_exit()`s with the already-decided exit code (0 after SIGTERM). Revisit on each DeepStream upgrade. | gdb backtrace of the main thread: `destroy_pipeline` (deepstream_app.c:2513) → `gst_element_set_state(NULL)` → `libnvdsgst_multistream.so` → `gst_pad_stop_task`; the muxer loop keeps logging "No Sources found at the input of muxer. Waiting for sources." Not fixed by clearing `drop-pipeline-eos` before teardown. Related reports: DeepStream forum threads on `set_state(NULL)` hangs with nvmultiurisrcbin in 9.1. |

| 10 | 2026-11-20 | docs/PARSERS.md "DeepStream adapter" (`NvDsInferParseObjectInfo{classId, left, top, width, height, detectionConfidence}`) | In DS 9.1 `NvDsInferParseObjectInfo` is a typedef of `NvDsInferObjectDetectionInfo`, which adds `rotation_angle` (OBB). The adapter zero-initialises every object (`rotation_angle = 0`, axis-aligned), drops class ids `>= numClassesConfigured` and clamps confidence to [0, 1], as the nvinfer contract requires. | `sources/includes/nvdsinfer.h:148-176`, `nvdsinfer_custom_impl.h:185-197` (DS 9.1). |
| 11 | 2026-11-20 | docs/PARSERS.md core types (`TensorView{const float* data, ...}`), families table | Clarifications, no contract change: (a) `TensorView` stays float-only; the adapter converts INT32/INT64 layers (EfficientNMS `num_dets`/`classes`) into per-thread float buffers, other types (e.g. HALF) fail with a one-time error. (b) Leading 1-sized dims are dropped only while the tensor has more dims than the family's rank, so a real single row `[1, 6]` is kept. (c) DETR `has_background_class`: the background is the **last** logit column. (d) `yolo_raw` expects `4 + C` channels without objectness (YOLOv5-style `5 + C` is not supported). (e) Without `RTVISION_PARSER_CONFIG` the adapter warns once and uses family defaults, output order and nvinfer's class count; a `parser.ini` whose `family` differs from the called function is an error. (f) `parser.ini` is parsed strictly (unknown keys/sections are errors). | `src/parsers/core/*.cpp`, `src/parsers/ds_adapter.cpp`, tests in `src/parsers/tests/`. |
